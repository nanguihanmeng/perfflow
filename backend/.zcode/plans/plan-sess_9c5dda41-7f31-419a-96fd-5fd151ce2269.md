## 考核审核逻辑与数据模型调整方案

### 需求确认
1. **部门领导在部门审核(DEPT_REVIEW)可直接编辑员工自评得分**（当前只能改完成率，且本部门得分对他脱敏）
2. **自评得分可见性**：员工本人 / 本部门领导 / LEAD / HR 可见；其他员工、其他部门领导不可见
3. **部门审核完点"提交"推送给领导**（现"通过"按钮）
4. **部门负责人**：由 role=DEPT_LEAD 决定，每部门唯一；admin 创建员工不再勾选"是否部门负责人"
5. **考核表信息栏"部门负责人"自动实时显示该部门领导名字**
6. **hr/admin 单独设计**：都不参与考核（不生成考核表），hr 改为无部门（dept_id=NULL）
7. **base_score 默认 0，由 HR 填写**（导入 Excel 时填指标分数）
8. **实时同步 perfflow.sql**

### 后端改动

**1. 自评得分可见性（AssessmentPermissionService.isRowMasked）**
- 改为按"当前用户能否看该表"判定：EMP 看自己→不脱敏；DEPT_LEAD 看本部门→不脱敏；LEAD/HR→不脱敏；其余→脱敏
- `ensureVisible`/`scopeOf` 已按角色限定范围，无需改

**2. 计算拆分（AssessmentCalcService）**
- `recalc` 改为**只求和 selfScore**（不再重算 selfScore），写 self_total_score
- 新增/保留 `calcSelfScore(baseScore, completionRate)`；员工改完成率、提交时先重算各非 BONUS 行 selfScore 再求和
- 部门领导改 selfScore 直接覆盖落库，recalc 只求和（不被完成率覆盖）

**3. 行更新分流（AssessmentRowService.update）**
- EMP（SELF_DRAFTING）：改 completionRate（0-100）→ 自动算 selfScore → 求和
- DEPT_LEAD（DEPT_REVIEW，本部门）：改 selfScore（0~该行指标分数）→ 覆盖落库 → 求和
- `canEditRow` 保持（DEPT_LEAD 已支持 DEPT_REVIEW）

**4. 部门审核提交（AssessmentTableService）**
- approve 逻辑不变（DEPT_REVIEW→LEAD_SCORING），流程日志 action 文案 "APPROVE" 保留；按钮语义改"提交"

**5. 部门负责人唯一（SysUserService）**
- `UserCreateReq`/`UserUpdateReq` 去掉 `deptLead` 字段；create/update 不再写 dept_lead（默认 0）
- 创建/编辑用户 role=DEPT_LEAD 时校验：该部门已存在其他 DEPT_LEAD → 报错"该部门已有部门负责人：XXX"（每部门唯一）
- `lookupDeptLeadName` 改为查 `role='DEPT_LEAD'` 的用户（不再用 dept_lead=1 标志），考核表信息栏自动实时显示

**6. hr/admin 不参与考核（AssessmentTableService.initForPeriod）**
- 生成考核表时跳过 role=ADMIN **和 role=HR**
- hr 用户 dept_id 改为 NULL、dept_lead 改 0（数据更新）

**7. base_score 默认 0（AssessmentTableService.createRowTemplate）**
- 10 行模板 baseScore 全部传 0；导入 Excel 时 HR 填指标分数写入 base_score
- assessment_row.base_score 加 DEFAULT 0（ALTER + perfflow.sql）

**8. perfflow.sql 同步**
- assessment_table 补 position 列（与线上库一致）
- assessment_row.base_score DEFAULT 0
- sys_user 种子：hr 无部门、去 deptLead 语义说明
- 同步所有本次 DDL/数据变更

### 前端改动
1. **UserManage.vue**：删除"部门负责人"开关（deptLead）；dto.ts 的 UserCreateReq/UserUpdateReq 去 deptLead
2. **AssessmentRows.vue**：编辑模式分流——EMP 编辑"完成率"，DEPT_LEAD 编辑"自评得分"（输入框 0~指标分数）
3. **AssessmentDetail.vue**：部门领导操作按钮"通过"改"**提交**"（确认文案"提交给领导评分"）
4. 信息栏"部门负责人"已由后端 deptLeadName 返回，自动更新

### 数据清理（保留审阅）
- 删除 hr 的考核表（2026Q3 的 id=4、2026 的 id=17，hr 不再参与考核）
- 删除孤儿考核表（user_id=4/5 已不存在的用户，2026Q3/2026 周期各若干）
- 现有 base_score 16/10/5 的历史行保留不动（仅新生成周期为 0）

### 验证
- 后端单测：recalc 求和、完成率重算、可见性逻辑
- 全链路 curl：HR 导入(含分数) → 员工填完成率 → 提交 → HR 推送 → **部门领导编辑自评得分** → **提交给领导** → 领导评分 → 验证最终分/等级
- 浏览器实测 DEPT_LEAD 视角：确认编辑自评得分按钮出现、可见性正确
- 权限矩阵验证：其他员工/其他部门领导看该表自评得分脱敏
- perfflow.sql 与线上库 diff 校验
- 打包重启，清理测试数据
